## 追加：修复“某些视角下格子变成竖条”（改成先旋转后按屏幕轴缩放）
- 现象/原因：`world()` 原来是「先按世界轴缩放（世界 x×cellW、世界 y×cellH），再按视角旋转」。视角是让**当前前进方向朝上**的，所以当路径沿世界 x 方向走时，格子的“宽（cellW）”被旋转到了屏幕竖直方向，格子看起来就是竖条（截图里的情况）；沿世界 y 走时才呈现横条。格子本身又是「跟随视角旋转」绘制的，进一步固化了这个现象。
- 修复（`js/scenes/game.js`）：
  1. `world()` 改为**先旋转到屏幕坐标系，再按屏幕横/纵分别缩放**：`v = rotateVec(Δx, Δy)` → `(anchorX + v.x*cellW, anchorY + v.y*cellH)`。由于旋转后“前进方向”恒为屏幕正上方，所以**沿前进方向的格距恒为 cellH**、**垂直前进方向的格距恒为 cellW**，与路线朝哪个世界方向无关。
  2. 格子不再 `ctx.rotate(this.rot)`，直接画成屏幕上横向的扁条 `cellW*0.76 × cellH*0.76`（圆角 `cellMin*0.18`）。
  3. 拐弯箭头方向改为「旋转到屏幕系 → 按屏幕轴缩放 → 归一化」，与新的坐标变换一致。
- 复核（node 复刻变换）：玩家在第 3 格（沿世界 x 段）与第 10 格（沿世界 y 段）两种情况下，沿前进方向的相邻格屏幕差都是 `(0,-60)`；拐弯处是 `(±107,0)`；格子屏幕尺寸恒为 81×46（宽×高，375 宽机型），即任何视角下都是横向扁条。
- 校验：客户端全部 JS 通过 `node --check`，`get_errors` 无错误。

## 追加：格子朝向跟随自身路段（拐弯前后刚好从纵向变横向）
- 需求：拐弯处那一段的三个格子，此刻应该是**纵向**的，这样等玩家走到拐角、视角转过 90° 后，它们刚好变成**横向**。
- 根因：上一版把格子画成“恒定屏幕横条”，同时 `world()` 是「先旋转、再按屏幕横/纵不同缩放」的非等比变换。两者互相矛盾——非等比变换意味着“垂直前进方向”的格距是 cellW、“沿前进方向”是 cellH，格子只能呈屏幕轴对齐的横条；而用户要的是“格子跟随自己所在那段路”的朝向。
- 改动（`js/scenes/game.js`）：
  1. `world()` 改为**刚性变换**：`rotateVec(Δ) * cellH`（统一用 cellH 缩放）。于是所有段沿自身前进方向的格距恒为 cellH，地图形状保持刚体（视角变化时整块棋盘纯旋转，不再有斜切/拉伸）。
  2. 新增 `dirAt(j)`：取第 j 格所属直线段的世界单位方向（非末格取“到下一格”，末格沿用上一格）。
  3. 格子绘制按本段方向旋转：`sd = rotateVec(dir)` → `tileRot = atan2(sd.x, -sd.y)`，再画 `cellW*0.76 × cellH*0.76` 的圆角矩形（沿前进方向 cellH、垂直方向 cellW）。因此当前段是横向扁条，**拐弯之后那一段此刻是纵向长条**，玩家转向后视角旋转 90°，它们自动变成横向。
  4. 同格玩家排列方向同步改为“本格横向”（`rotateVec(-dir.y, dir.x)`）：在玩家自己所在段上（前方朝上）依然是**屏幕横向**，而其它段上的玩家与自己的竖格方向一致，不会横着溢出格子。
  5. 拐弯箭头方向简化为 `rotateVec(dOut)` 归一化（刚性变换下方向即真实屏幕方向）。
