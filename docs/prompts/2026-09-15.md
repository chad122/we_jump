# 需求记录 2026-09-15

## 追加：并发/健壮性 6 项优化（承接 2026-09-13 的全局排查结论）
- 需求：上一轮排查报告里"待定策略"的 6 项，全部落实：1 要、2 加、3 要、4 加、5 优化、6 优化。

1. **房间泄漏回收（1）**
   - `Room` 新增 `LastActiveAt`（`Touch()` 刷新）与 `Touch()` 调用点：`AddPlayer`/`RemovePlayer`/`AttachSession`/`DetachSession`/`TrySelectMap`/`SetPhase`/`ResetReady`/`Broadcast`（任何消息往来都会续命）。
   - `RoomManager.SweepIdleRooms()` 改为：**全员离线 且 超过闲置时限** 即回收，时限按阶段区分 —— 等待房 **10 分钟**（`IdleWaitingTtl`）、对局中/已结束 **30 分钟**（`IdleOtherTtl`，留足断线重连时间）；回收时清空成员映射。
   - 说明：原规则只看 `Waiting` + `CreatedAt`，`Playing/Ended` 且全员离线的房间永不回收。

2. **`Phase`/`Engine`/`Aborted` 线程安全（2）**
   - `Room`：三个成员改为**加锁属性**（`_sync`，lock 可重入，类内部已持锁处直接调用也安全），并统一改为内部字段 `_phase`/`_engine`/`_aborted`；`TrySelectMap` 内部读取也改用字段。
   - 效果：`RoomManager`/`GameHub`/引擎在不同线程读写不再有可见性/竞态问题。

3. **同账号多端：踢掉旧连接（3）**
   - `WsSession.Kick(json)`：把下线提示排进发送队列并置 `_closeAfterFlush`，writer 发出这条后**优雅关闭**（保证客户端能收到提示再停止重连）；`TrySend` 在已踢下线后不再排队。
   - `RoomManager` 新增 `_userSession`（userId → 当前连接）与 `RegisterSession()`；`GameHub.RunAsync` 在鉴权后调用 → 旧连接收到 `kicked{msg:"账号已在其他设备登录，本机已下线"}` 后被关闭。
   - `OnSessionClosed` 只清理自己那条连接登记（不误删后来居上的新连接）。
   - 客户端：`case 'kicked'` → `state.kicked = true` + `state.ws.detach()` + 回主菜单 + toast；`App.send` 在被踢状态下用户再次操作会**主动重连**（`relogin('已重新连接，请再点一次')`），避免"本机永久离线"的死胡同；`connectWs.onOpen` 成功时清 `state.kicked`。

4. **客户端 `room_state` 房间号守卫（4）**
   - `app.js`：`case 'room_state'` 增加 `if (state.room && data.roomNo && state.room.roomNo !== data.roomNo) return;` —— 退房瞬间收到的旧房间迟到广播不再覆盖新房间状态。

5. **旧连接回调解绑（5）**
   - `net.js` 新增 `WsClient.prototype.detach()`：置空 `onOpen/onMessage/onError/onClose` + `close()`（同时关掉自动重连）。
   - `App.relogin()` 改用 `detach()` 丢弃旧连接，旧连接的迟到消息不会再被路由到 App。

6. **反作弊：蓄力时长服务端校正（6）**
   - `GameEngine.SubmitJump()`：新增 `_liveAt`（进入可跳跃状态的时刻，作为首次跳跃的蓄力基准）；按 `sinceMs = now − 上次跳跃时间`（首次用 `_liveAt`）算出 `maxChargeMs = sinceMs − 500ms`，把客户端上报的 `elapsedMs` **截断**到该上限。
   - 效果（node 校验）：正常玩家（700ms 冷却 + 真实蓄力，含 100ms 负向网络抖动）**从不被截断**；伪造"冷却期没走完就上报满蓄力"会被截到 200ms、极限情况截到 0ms（最终仍保底 1 格）→ 作弊收益远低于老实蓄力。
